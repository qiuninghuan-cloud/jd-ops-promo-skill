# 自营供应商经营工作法

适用于“今天看什么、怎么经营、做周报/月报、跟采销、核利润”等综合任务。计算与证据定义沿用 `decision_rules.md`；记录结构用 `../assets/operations_workbook.md`。处理单个标题时不必展开本工作法。

## 经营目标先于工具

开工先确认用户本期主目标：广告后贡献额、供货收入、回款、缺货治理或库存去化。只选一个主目标，其他作为约束；用户未设目标时先做经营体检，列目标待定，不编增长率、预算或毛利底线。

将目标拆到有供货能力的 SKU、责任人和截止日。收入目标、利润目标和现金目标分别记录：采购/入仓不是消费者售出，售出不是已结算收入，结算收入也不是到账现金。

目标表至少有本期目标、实际、差额、进度日期、预计结果及假设。时间进度只能作参考，大促等非均匀经营周期按实际节奏判断，不简单按天外推。缺成本时先查可核实的收入、消耗和库存，利润列待填。

## SKU 是经营的基本单元

为每个 SKU 关联五类记录：产品事实、当前在售与价格、供货成本、SKU×仓库存、推广与经营结果。主键为 SKU ID，规格/装数/箱规分别保存；计划 ID 与 SKU 用关联表连接，一个 SKU 多计划时先核对再汇总。不同时间粒度的数据保留各自日期，不能强拼成同日事实。

分组按经营角色而非只按销售额：

| 角色 | 判断依据 | 本期动作 |
|---|---|---|
| 利润主力 | 贡献额已核实，库存与供货稳定 | 在损失与供给约束内测试放量 |
| 引流款 | 直接贡献较低且有可验证的关联价值 | 单列获客损失上限；关联价值未知则不宣称赚钱 |
| 成长款 | 有需求信号，样本不足 | 小规模验证产品、素材与流量匹配 |
| 库存处置款 | 临期/滞销风险可核实 | 测算去化与持有损失，协调采销；不盲目提高佣金 |
| 待核实/不可投 | 状态、资质或关键事实不明确 | 补证或排障，不纳入常规加投池 |

角色可随周期调整，记录原因；不能仅因一次 ROI 高就升为主推。新品立项与当前可投池分开管理。

## 每日巡检：先止损和保供

用户发起巡检时按下列顺序读当前数据。没有调度任务时不声称会自动每日查看。

1. 核对账户、数据更新时间、日期与归因；查看上次未完成事项和已实际执行的变更。
2. 看商品是否在售、库存/在途、余额和计划状态，找影响成交的阻断；再看费用与转化。
3. 查消耗是否超过已定上限、CPC/CVR 是否偏离可比基线、关键 SKU 是否缺货、价格/促销是否变更、是否出现集中投诉。
4. 对异常交叉核对商品、计划、仓库和变更时间；先分辨业务变化与报表延迟。缺权限记录具体缺口，继续完成可读部分。
5. 默认给最多三项优先动作，附证据、对象 ID、责任人、截止时间和复核点；其余放待办。紧急阻断全部列出，不为凑三条隐藏风险。

优先级按实际后果：P0 为产品安全/资质阻断、失控消耗或关键断供等需立即升级的问题；P1 为已验证且持续损害经营目标的问题；P2 为实验和改进。响应时间按团队约定或事件截止日填写，不虚构平台 SLA。

“没有异常”只代表已检查范围内未发现异常；列明未读到的维度。基线、阈值缺失时先建立可比基线，不宣称正常。

## 异常处理路线

| 现象 | 先核对 | 再追原因 | 交付与复核 |
|---|---|---|---|
| 消耗突增 | 日期/计费范围、预算、计划变更 | 新定向/版位、竞价和促销变化 | 与批准上限对比；给限额/降价建议，复核消耗及损失 |
| 成交或 CVR 下滑 | 归因延迟、样本、缺货和价格 | 流量结构、落地页、规格、评价与竞品 | 按证据排原因，只改已定位环节；复核成熟转化 |
| CTR 下滑 | 同版位展现/点击、人群与设备 | 素材、排名和流量结构 | 单变量测图，保留对照；看贡献额而非只看 CTR |
| 商品下柜/不可投 | SKU 状态与真实原因提示 | 资质/素材/供应/权限，向对应负责人核实 | 暂停加投建议、修复材料与复核清单；重新在售后再入池 |
| 缺货或滞销 | SKU×仓可用、在途到货、近期待售 | 偏仓、断货抑制销量、预测和提前期 | 先调拨可行性再补货/去化，核到货与周转 |
| 差评集中 | 去重后的实际评价/售后类型 | 批次、包装、物流、使用预期与产品问题 | 售后及质量负责人跟进；涉及安全先升级，回复不代替处理 |
| 收入不错但回款少 | 结算周期、对账单与到账记录 | 未结算、扣款、退货及争议款 | 建差异清单，定位单据与责任人，不归因成广告无效 |

## 每周经营会：决定下周资源

使用同一完整周期，未成熟归因单列。回答：目标差多少、哪些 SKU 贡献或拖累、原因有何证据、上周动作是否兑现。

预算按 SKU 贡献、成熟表现、可放量空间与库存能力分配；先确认库存能支撑、成本可核实，再提放量。不同工具只在目标确实需要且账户有权限时引入，不为覆盖工具清单而分散预算。保留试验预算上限，不把表现好的小样本直接复制成大计划。

供货需求与促销、广告排期同步；库存不足时先保供或缩量，不能营销与供应各自做计划。周会最多确定三项重点及其验收条件，保留所有紧急事项；上周未完成项明确阻塞原因或取消依据。

## 采销协同：把请求变成可处理的提报

价格、活动资源、新 SKU、组合装、资质整改及入仓安排，先查本账户实际权限，再区分自主处理与采销/平台处理。不要由历史经验断言供应商可以自行改前台价或拥有某资源。

提报包含：需求 ID、关联 SKU、目标/问题、现状证据、请求事项、供货报价与费用承担、库存与到货承诺、素材/资质路径、截止日、备选方案、接收人及状态。未知费用和供给承诺保留待确认，不能代作承诺。

状态流：草稿→待提交→已提交→待反馈→待补材料/已同意/已拒绝→待落地→已验证→关闭。仅收到“同意”不能标完成，还要检查实际价格、活动展示、上柜或到货结果。记录最近沟通时间和下次跟进日；到期未回复列升级建议。

生成提报稿不代表已发送。联系采销或其他人仍以用户明确授权和可用工具为准。

## 每月结算与现金复盘

把经营表现、结算收益与现金到账分成三张表，逐张对账。经营表用于解释销售与广告，结算表使用供应商对账单的真实入账基础，现金表按实际到账日；三者因周期差异不必同月相等。

结算链：期初应收 + 本期确认应收 - 本期核销/收款 - 调减 = 期末应收；先定义调增调减和含税范围，再勾稽账单。退款/退货、返利、活动分摊、广告费、物流、赔付与其他扣款逐项记录单据、所属期间和是否已扣，避免重复计费。

无法关联 SKU 的账户级费用单列“待分摊”，分摊需约定驱动因素并保留原额，不随意均摊得出 SKU 盈亏。广告归因成交不得直接当结算收入；采购入仓也不能直接当终端销售。贡献额并非包含全部固定费用后的净利润。

月报交付：目标与实际、SKU 贡献与库存、费用及回款差异、已验证动作、未解决事项、下月资源安排。报表缺失时给待对账项目和可确认的小计，不编造闭合数字。

## 完成标准

可追溯的数据范围、按影响排序的问题、能执行的任务、责任人与复核日、明确的执行状态同时齐备，才算一次综合经营交付完成。台账沿用用户现有文件与字段；无模板时才用配套结构，未知值留空并标待核实。修改经营记录保留日期和来源；历史快照不能覆盖成“当前状态”。
