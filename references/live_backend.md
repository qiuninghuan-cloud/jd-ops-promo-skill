# 京东后台操作与证据

## 连接与恢复

1. 查看本轮实际可调用的工具，按对应浏览器/电脑操作技能连接用户现有已登录标签页。成功读到页面和账户信息后，才能声明连接成功。历史 tab ID、会话名只是线索。
2. 优先复用当前登录。京准通常用入口 https://jzt.jd.com/ ，自营商智可从 https://jdsz.jd.com/szweb/view/index/home.html 进入；以账号实际导航为准。某个旧入口无权限不等于整个账号无权限。
3. 工具未暴露时可先发现可用工具；已连接但失败时根据具体错误做一次有依据的恢复检查。同一错误重复出现且没有新线索就说明阻塞点，保留进度，不循环要求重启或重新安装。未经成功检查不承诺“重启就能操作”。
4. 登录、验证码或二次验证确实要求本人时才请用户接管该步。正常导航、筛选、导出由代理完成。无需索取密码或导出 Cookie，结束时不擅自退出用户会话。

## 读取口径

- 先核对店铺名、广告账户、币种、页面日期和筛选条件。默认最近 7/30 个完整自然日，排除今天；把实际起止日期写出来。“本月”不能替代“最近30天”。当日数据单独标明未完整。
- 记录报表归因方式、回溯天数、是否包括间接成交、退款及赠款。延迟归因期内的数据标记未成熟；比较趋势优先选归因成熟度一致的窗口。
- 将每个值与可见列名对应，表格横向滚动/自定义列后重新核对。花费、CPM、CPC 分开记录。金额截断或表头不明时打开详情或导出，不能靠位置猜列。
- 使用 `promo_roi_playbook.md` 的公式交叉核验 CPC/CPM/ROAS；明显不符先处理字段、单位或筛选问题。保留页面显示值及其四舍五入差异。
- 账户→所有计划（含分页和暂停项）→单元/SKU→相关搜索词/人群。记录 ID、状态、预算、商品归属、实际花费与成交。按任务所需读取，不要求无关字段齐全才开始工作。
- 商品报告记录 SKU ID、规格、成交量/额、成交均价、价格优惠、在售状态和可售库存。父商品展示价不能代替子 SKU 到手价；库存分区域时看主要销售地区。
- “自然销量好”必须有来源分拆，并注明自然搜索/推荐等具体渠道。店铺总销量仅称总销量；商智总成交与广告归因成交可能交叉、跨期，不能直接相减求自然成交。
- 缺失数据写明未提供，成本无法取得时保留盈利判断的不确定性。报告优先读取聚合数据，避免导出无关买家姓名、地址和联系方式。

## 授权与预算

- 读取、筛选、普通报表导出直接执行。已明确授权的具体调整，或授权范围内的管理任务，准备好具体变更即可执行，不逐步重复确认。
- “全权推广”不等于无限预算。核实账户及计划预算、实际消耗、可用余额、自动追加开关、投放期限；已有日预算上限不能自动当作用户批准的新增测试预算。
- 用户要求拆 SKU 可先完成选品、重叠检查及表单准备。新支出额度缺失时，提出具体预算来源、总上限、测试期限和止损额后仅询问这一缺口；平台支持时可保存为不投放草稿，先核实创建默认状态。
- 不把读数授权扩大到充值、价格/优惠券、商品发布、活动报名或消息发送。超出既有范围时只确认新增范围。

## 写入与验证

1. 写入前形成简短变更单：对象 ID、旧值→新值、理由、预算来源与前后总上限、恢复方式。
2. 先查是否已有同 SKU 同目的计划；断线后先查询结果再重试，防止重复创建。不可直接复制多个同质计划来放量。
3. 保存后重新读详情/列表：计划 ID、唯一 SKU、状态、预算、出价方式/目标、投放日期。提交超时且状态未知时只读查询，不盲目再次提交。
4. 错误店铺、预算超界或保存值不符时停止后续相关写入，查明已发生的改动；按已授权恢复范围处理，不用推测覆盖现值。
5. 多步或跨会话工作在用户工作区留一份简短操作记录：时间、报表口径/证据路径、授权范围、变更前后值、验证结果、未完成项。仅记录必要经营数据，不存凭据。恢复时先核对实际状态，旧聊天结论不作为实时数据。
