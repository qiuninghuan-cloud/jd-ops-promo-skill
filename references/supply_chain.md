# 京东供应链与补货（自营供应商 · 12 仓场景）

> **场景前提**：我们是自营供应商，货入**京东全国仓**，用户下单后由京东仓发货。
> 「补货」= 往京东仓补我们的货。可用库存、在途、出库均以**京麦后台**数据为准。

---

## 一、先统一口径（每次补货前必看）

| 术语 | 含义 | 京麦取数位置 |
|---|---|---|
| **近7日出库** | 该仓最近 7 天发给用户的件数（= 京东真实动销） | 库存/报表 → 销售出库报表，按仓导出 |
| **可用库存** | 京东仓里当前可卖的我们的货 | 库存管理 → 各仓库存查询 |
| **采购未到货（在途）** | 已下单/在途、还没入仓的件数 | 采购单/入仓单列表 |
| **提前期 L** | 从补货指令到货到仓可售的天数（含在途运输+入库上架） | 按历史入仓单实测，通常 3–10 天 |

> ⚠️ 出库≠订单量。一单可能发多件，补货按**件数**算，不按订单数算。

---

## 二、补货公式（三层，从简到全）

### 第 1 层：基础版（现行公式，标准化）

```
补货量 = max(0, ceil( 近7日出库 ÷ 7 × 覆盖天数 − 可用库存 − 采购未到货 ))
```

- 现行覆盖天数 = **20 天**，本质是「把库存补到能卖 20 天的水平」。
- 向上取整（按箱/件的最小包装取整），结果不为负。
- **优点**：简单、三列数就能算，适合周例行。
- **盲点**：① 没区分供应提前期长短；② 没有应对销量波动的安全库存；③ 大促/季节波动没体现。

### 第 2 层：进阶版（日常推荐）

```
补货量 = max(0, ceil( 日均销 × (提前期 L + 覆盖天数) + 安全库存 − 可用库存 − 采购未到货 ))

其中：
  日均销     = 近7日出库 ÷ 7
  安全库存   = 日均销 × 波动天数（不会算波动就用 3–7 天）
```

- 提前期长的仓（远的慢仓、大促前物流紧）覆盖天数要相应拉长，否则补货在路上就断货。
- 安全库存是给"突然多卖"留的缓冲——爆款断一次货，前台权重和排名掉得比补货成本贵得多。

### 第 3 层：分层覆盖天数（不要全店一个 20）

按仓/按 SKU 分三层，而不是所有仓统一 20 天：

| 层级 | 判据（按仓按 SKU） | 覆盖天数 | 逻辑 |
|---|---|---|---|
| **A 爆款仓** | 日出库 ≥ 10 件 | **18–22 天** | 走量快、采销盯得紧，断供代价最大；提前期短可略压 |
| **B 常规仓** | 日出库 3–9 件 | **22–26 天** | 平衡断货与滞销 |
| **C 慢销仓/长尾 SKU** | 日出库 < 3 件 | **25–30 天** | 补货频次降下来，小批量多次，避免压仓 |

### 第 4 层：大促版（双 11 / 618）

```
大促补货量 = max(0, ceil( 日均销 × 大促系数 × (提前期 L + 覆盖天数) − 可用 − 在途 ))

大促系数：按去年同促销量 ÷ 平日销量估；无历史数据时保守取 2.5–3
覆盖天数：平时的 2–2.5 倍（大促物流慢+入仓排队）
```

**大促三条军规**：
1. **分 2–3 批入仓**——一批全押，卖爆了断货、卖不动了压死；首批 60% 提前入仓，二批 30% 促中前补，三批 10% 视动销补。
2. **入仓截止日倒排**——京东仓大促前会收紧入仓（一般提前 7–15 天截止），补货计划必须按**入仓截止日 − 提前期 L** 倒排下单日，不是按开卖日。
3. **滞销品不硬囤**——覆盖天数拉长只对动销品，C 层品大促照常小补。

## 三、滞销与缺货的权衡（公式背后的决策）

| 情况 | 判据 | 动作 |
|---|---|---|
| **滞销预警** | 可用库存 > 近 30 天出库（≈ 30 天卖不完） | 停止补货；报采销做活动/调拨消化；临期品优先处理 |
| **慢仓积压** | 某仓补货量算出来是 0 且库存高 | **优先走仓间调拨**（京麦调拨申请），比跨仓补货省运费也省入仓 |
| **断货风险** | 可用库存 < 日均销 × (L + 3) | 立即补，哪怕不够一箱也补；爆款断货掉权重 |
| **零出库** | 近 7 天出库 = 0 | 不补；先查是不是前台下架/无流量，再查是不是仓间缺货 |

**核心权衡**：覆盖天数每加 1 天，断货风险降一点、滞销和资金占用升一点。
自营的断货代价（前台不可售 + 采销考核 + 排名下滑）通常**高于**多压 5 天货的成本——所以偏保守，爆款宁多勿少。

## 四、周例行补货 SOP（固定动作，每周一次）

1. **导三张表**（同一天，保证口径一致）：
   - 近 7 天各仓出库明细（SKU × 仓）
   - 当前各仓可用库存（SKU × 仓）
   - 在途/采购未到货（SKU × 仓）
2. **对齐 SKU 编码**：三张表的 SKU 命名/编码可能不一致，先用商品编码对齐再合并。
3. **套公式算补货量**（按 SKU × 仓逐行；用 `scripts/calc_restock.py` 批量算）。
4. **过一遍异常清单**：补货量为 0 的、滞销预警的、在途但库存为 0 的。
5. **输出 Excel 多 Sheet**（沿用用户既有模板，**不改表头，只填结果列**）：

| Sheet | 内容 |
|---|---|
| 仓库汇总 | 每个仓的补货总件数、涉及 SKU 数、总金额（可选） |
| 补货明细 | SKU × 仓 的补货量、公式中间值（日均销/可用/在途） |
| 滞销与调拨建议 | 滞销 SKU、建议调拨的仓对、暂停补货清单 |

6. **提交**：京麦补货/采购单按明细下单，在途数量回写（下次计算的"采购未到货"就有了）。

## 五、calc_restock.py 用法

```bash
# 输入 CSV 需含列：sku,warehouse,out7,stock,intransit
#   out7=近7日出库件数  stock=可用库存  intransit=采购未到货

python3 "$SKILL_DIR/scripts/calc_restock.py" restock.csv
python3 "$SKILL_DIR/scripts/calc_restock.py" restock.csv --cover 22 --safety-days 5 --lead 7
python3 "$SKILL_DIR/scripts/calc_restock.py" restock.csv --out 补货结果.csv
```

- 默认参数就是第 2 层进阶版：`--cover 20 --safety-days 5 --lead 7`
- 输出：每行补货量（向上取整、不低于 0）+ 按仓汇总 + 滞销标记 + JSON/CSV
- 分层覆盖天数可用 `--cover-by-tier` 自动按日出库分 A/B/C 层套不同天数

**输入 CSV 示例**：

```csv
sku,warehouse,out7,stock,intransit
100038874722,北京仓,84,120,60
100038874722,广州仓,63,40,0
100017283385,上海仓,7,55,0
```

## 六、常见错误（都犯过，列出来防再犯）

| 错误 | 后果 |
|---|---|
| 用**订单数**当出库量 | 一单多件时少补一半以上 |
| 用**全国汇总**算补货量再平分到仓 | 爆量仓断货、慢仓压货——必须按仓单独算 |
| 忘了减**采购未到货** | 重复下单，货到仓爆仓、滞销 |
| 覆盖天数全店统一 | 慢销品压死、爆款断供 |
| 大促按开卖日倒排 | 没算入仓截止日和排队，货卖爆了货还在路上 |
| 出库数据跨月/含退货未剔 | 退货拉高出库假象，取数要确认是净出库 |
