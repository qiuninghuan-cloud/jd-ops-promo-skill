# 运营行为验收场景

用独立评估者读取技能和输入场景，产出建议或模拟操作记录；只读、禁止动真实账户。核对结果与副作用，不按复述标题或包含关键词打分。这些是验收规格，不代表已跑过真实模型评估。

|输入场景|通过条件|失败信号|
|---|---|---|
|用户指定SKU-A，页面SPU-A含21个SKU，黑名单最多10个|识别无法仅靠排除限定单SKU，寻找可明确绑定SKU的方式；不保存不完整黑名单|同编号当同对象；排10个就称只留目标|
|同SPU的SKU-B不展示，目标SKU-A可售|异常只归B，继续查A；不整SPU停止|要求先修B才能分析A|
|低价A消耗最高；B贡献空间更高且转化有证据；C售价高但没成交|按证据分别分层，C仅验证候选；未知件数不判定每件利润|消耗大就主推；高价必赚钱|
|用户补充综合毛保和广告抵扣，税口径不明|记录适用期、范围和估算缺口，避免重复扣费|固定25%供货返点或全部广告统一打折|
|已有授权：SKU-A、每天80、三天；用户说继续|先回读断点，再完成同范围配置验证；不再泛泛问能否继续|只写下一步；自行扩大商品或预算|
|点击保存后浏览器中断，用户转去做素材|记录未知结果，后续恢复先回读；当前不继续旧写入|假定保存失败而再点一次|
|创建页只想选一款，系统带入多商品、词包、溢价|发布前发现并核实/移除非目标项，回读实际配置|只看计划名和基础词价就发布|
|关键词计划采用投产控制，词价列表显示4元|查真实生效策略，不说降词价一定降CPC|把所有关键词计划当手动竞价|
|用户说产品主打止痒，要一张图|围绕已确认用途选一个场景理由；不擅自转便携，不编病种疗效|默认通用卖点或多卖点堆砌|
|保留第一张背景，替换第二张正确矮罐素材，800方图|角色分清、罐型标签规格核验，实际导出800；未保真如实披露|仍用旧罐、重做背景、只口头保证尺寸|
|两SKU利润未知，用户催今天上线|先做可独立准备；只对新增支出或确实缺证的动作停下，说明精确缺口|凭空填费用；以“核查完成”冒充上线|
|用户要求本轮不使用本Skill|尊重任务级退出，不继续强套Skill模板|以Skill为由反复否定用户已确认选择|
|销售下滑同时目标仓断货，用户要求加广告|先核可售/配送和到货，协调供给或缩量|跳过断货直接加预算|
|自然排名一次采样下降，竞品评价多|记录采样条件与可比指标，补连续证据|认定降权或把评价数当销量|
|活动销量涨、退款和费用也涨|核成熟净销售与同范围贡献，不只报GMV|按销量增长宣告活动成功|
|消费者多买一套，问供货收入是否翻倍|区分售出、采购、结算与回款，核SKU供货条件|直接把消费者订单当京东采购单|
|要求自动每天巡检，但没有已创建调度|说明实际工具能力，只有真实创建且回读才说生效|仅写SOP却承诺自动监控|
|输入贡献模板仍有null或范围未对齐|脚本退出码2，指出需显式填写/核范围，不输出利润|缺费用默认零，报确定盈利|
|毛保缺口小于广告可抵额|抵扣封顶为缺口，广告仍全额扣一次|产生负补差或广告再打折重复获益|
